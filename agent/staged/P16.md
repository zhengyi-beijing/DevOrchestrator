# P16 AI Capability Benchmark Project

Status: **PENDING DESIGN**

Goal: create a separate, reproducible benchmark project that measures the real capability, efficiency and reliability of the AI resources available to DevO/AIBroker, and determines when shared repository retrieval such as zvec-grep should become a standard Agent Harness capability.

Scope:
- Create an isolated benchmark repository/project with frozen tasks, seeded defects, architecture questions, cross-file reasoning cases, implementation tasks, review tasks and debugging/root-cause tasks with known ground truth.
- Evaluate AI resources by role rather than by model reputation: Planner, Reviewer, Worker/Implementer and Debugger/Root-cause Analyst.
- Include the currently available model families where usable, such as Codex GPT-5.6 Sol, Claude Opus/Sonnet, ChatGPT Web Sol, AGY Gemini Pro/Flash and Copilot models; resource discovery must be runtime-driven so the suite survives model changes.
- Run repeated trials with fixed task, prompt, repository revision, tool policy, timeout and scoring rubric.
- Record correctness, evidence completeness, false findings, missed findings, patch validity, regression rate, tool calls, input/output token usage when reported, wall time, retries/failover, quota consumption and provider/model identity.
- Keep benchmark execution isolated from production repositories and never allow benchmark tasks to mutate DevO, LabDemo or xray-hw-platform source trees.

Repository Retrieval A/B track:
- Track A: native project tools only (exact grep/rg, file read, git, tests and ordinary agent tools).
- Track B: the same AI/task plus zvec-grep semantic/BM25/vector retrieval, followed by exact source verification.
- Hold model, prompt, task, repository revision, timeout and scoring constant between A/B pairs.
- Measure whether zvec-grep reduces discovery time, tool calls and context/token use while preserving or improving correctness and evidence quality.
- Test representative questions where the exact symbol/location is unknown, including architecture ownership, cross-file call/data flow, design rationale, hidden compatibility paths and relevant-test discovery.
- Exact identifiers/regex/exhaustive occurrences remain on native rg/grep; zvec-grep is a discovery/ranking layer, not authoritative evidence.

Promotion gate:
- zvec-grep must not become a mandatory DevO dependency solely because it benchmarks well once.
- Promote it into the Agent Harness as the shared Repository Retrieval layer only after repeated A/B results show a meaningful benefit on representative development/review tasks without unacceptable stale-index, false-retrieval, latency, privacy or maintenance costs.
- If promoted, all roles may use the same workspace index through a bounded Harness interface; models reason over retrieved evidence, while repository truth, git, exact source reads, tests and lifecycle authority remain independent.
- Preserve a native-tool fallback so project development continues when zvec-grep/indexing is unavailable.

Acceptance:
- A clean benchmark run can compare at least three distinct AI resources across at least Planner, Reviewer and Worker/Debugger task classes with repeatable ground-truth scoring.
- Results clearly separate model capability from retrieval/tooling effects and expose provider/model/quota/session metadata.
- At least one paired native-vs-zvec-grep experiment is reproducible and reports accuracy/evidence quality, tool calls, token/context usage where available and wall time.
- The benchmark produces machine-readable results plus a human-readable comparison report without ranking resources through undocumented subjective impressions.
- A documented promotion/no-promotion decision can be made for zvec-grep as an Agent Harness Repository Retrieval component based on the measured evidence.

Design note: P16 is a benchmark/test project, not a production feature phase. Detailed benchmark corpus, scoring rubric and statistical repeat policy must be frozen before comparative runs.
