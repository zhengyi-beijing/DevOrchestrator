## P20.1 contract and storage design

Add a versioned FailureIncident contract to the existing incidents package.
Required fields: schema_version, incident_id, project_id, task_id,
execution_id, plan_id, review_id, lifecycle_generation,
lifecycle_transition_id, recovery_epoch_id, failure_signature,
failure_family, failure_class, stage, role, provider, model, resource, account,
first_seen_at, last_seen_at, occurrence_count, evidence, root_cause_hint,
previous_attempts, recovery_strategy, recovery_attempt, recovery_result,
recovery_latency, terminal_disposition, owner_gate_id,
regression_candidate_id, related_incident_ids. Nullable evidence stays null,
never inferred as a successful result. Schema validation rejects malformed
durable records and unsupported versions before recovery can use them.

Classes: malformed_ai_output, planner_timeout, worker_process_lost,
reviewer_rejected, reviewer_timeout, provider_quota_exhausted,
provider_unavailable, aibroker_unavailable, daemon_restart_during_execution,
daemon_restart_during_handoff, stale_head, unexpected_dirty_worktree,
missing_execution_record, lost_handoff, duplicate_request,
lifecycle_projection_mismatch, retry_without_progress,
transport_unavailable, unknown_requires_owner.

Signature uses normalized allowlisted semantic facts and excludes random IDs,
timestamps, absolute paths, account rotation and prompt text. Reuse the
existing fingerprint boundary; family identity remains stable across restart.
Keep project isolation explicit in store identity. Idempotency is checked
inside the existing store lock, not against a stale pre-transaction snapshot.
An occurrence key is a durable source-event identity, not a new daemon tick.
Journal intent -> verified immutable evidence -> atomic index commit; replay
must apply or confirm exactly once. Mutation must not erase old index data.
Persistent corruption/unverified evidence fails closed across new instances.

Sanitize before ANY persisted index, packet, candidate or journal bytes.
Reuse secret redaction and cover embedded assignments, Authorization/Bearer,
API keys, passwords, PEM and nested env/prompt content. Do not persist full
prompts or environment dumps; prefer bounded typed evidence references.
Use bounded evidence, candidate corpus and journal/retention limits with
explicit backpressure/owner gate on capacity exhaustion. Never evict replay
dedup keys in a way that permits re-actuation or silently loses failures.
Compaction preserves totals, family identity, verified status and audit chain.

Telemetry is an observation projection, never execution authority:
manual_continue_count, automatic_recovery_count,
automatic_recovery_success_count, owner_gate_count,
duplicate_execution_count, duplicate_job_count, duplicate_handoff_count,
duplicate_successor_activation_count, failure_incident_count,
repeated_failure_family_count, recovery_latency_seconds,
task_completion_count, review_acceptance_count, daemon_restart_count,
lifecycle_invariant_escape_count. Counters are durable source-event based,
restart-idempotent, run-scoped; unknown coverage is not numeric zero.
An invariant escape means an invalid state affected actuation/authority before
detection. A launch fenced before effects is not an escape.

## P20.2 harvesting and regression design

Extend current detectors and terminal event boundaries for Planner, Worker,
Reviewer, Watchdog, TransitionExecutor, daemon/restart, AIBroker/resource
routing, ExecutionTransport and DurableJob. Capture available authority and
source identities; classify unavailable/ambiguous evidence as unknown, never
successful. Each repeated signature attaches to the same project family;
replaying a terminal event does not increment it again.

RegressionCandidate adds candidate_id, incident/family source, minimal
reproduction context, expected invariant, actual result, proposed regression
class, replayability and verification_status (proposed, reproducible,
verified, rejected, promoted). A bounded JSON fixture/corpus invokes actual
deterministic production logic through an allowlisted replay runner; do not
execute model-generated arbitrary Python as acceptance proof. Verification
must discriminate the incident from corrected behavior, run repeatably and
persist rejection reasons. Promotion means verified runtime evidence, not
editing tests_py in the running daemon. Permanent tests require a later normal
Worker/review change. Corrupt incidents cannot verify or recover.

## P20.3 recovery design

A pure decision policy consumes current lifecycle authority, incident/family,
durable previous attempts, resource availability and finite policy budgets.
Outputs only RETRY_SAME_STRATEGY, RETRY_CHANGED_STRATEGY, SWITCH_RESOURCE,
HETEROGENEOUS_ESCALATION, RESTART_COMPONENT, RECONCILE_RUNTIME, OWNER_GATE,
NO_ACTION_ALREADY_RECOVERED plus reason, authorized effect, finite remaining
budget and exact expected authority/source anchor. It is not another state
machine. Existing coordinators enforce owner, clean Git, idempotency and role
independence again immediately before actuation. Persist attempt reservation
before effect and outcome afterwards; crash ambiguity reconciles the existing
effect/job identity or gates, never starts an unproven second Worker/job.

Default same-strategy retries are at most one; total recoveries per incident
are at most three. Repeated unchanged semantic failure requires a verifiable
changed strategy/context/model/provider/repair plan. Merely changing AGY
account does not qualify. High-risk/semantic/architecture failures require
heterogeneous escalation with an available eligible resource or OWNER_GATE.
Luna mechanical / Terra engineering / Sol complex labels guide policy only
when actual configured resources support them. Do not fabricate models.
Provider-independent review remains independent from implementation.
Stale HEAD, unsafe dirt, contradictory lineage, safety/authorization changes
and exhausted ambiguity gate. Gates are stable, durable, actionable, owned
once and inhibit all background actuation. Restart remembers attempts and
escalation; resolved old incidents never re-actuate.

## P20.4 isolated harness and live qualification

Create a tracked reproducible pure-software template and harness. Generated
Git repo and runtime live outside the production checkout; explicit CLI-local
soak permit ties canonicalized repo/runtime paths, run ID and dedicated
project ID. Production default OFF. No ordinary HTTP/MCP/browser request can
enable faults. Test disposable markers, traversal, symlinks, overlap with
canonical runtime, wrong project and missing permit. Every injected fault is
persisted before injection and correlated with an incident and outcome.

Five consecutive real tasks: feature with tests, failing edge-case fix,
behavior-preserving refactor, parser/data-validation fix, bounded API with
tests. Each uses real Planner -> independent Plan Review -> Worker -> tests ->
Git commit -> independent Technical Review -> accepted lifecycle handoff,
real AIBroker routing and durable jobs. Mock providers are allowed for earlier
deterministic tests only. Require actual test and review evidence per task.

Faults (all must be tested): malformed Planner output, Planner timeout, Worker
killed once, Reviewer reject, quota exhausted, provider unavailable, broker
unavailable, active-task daemon restart, handoff daemon restart, stale HEAD,
unexpected dirt, missing execution projection, lost handoff, duplicate retry,
repeated same signature. Model unsafe cases as isolated child probes or
terminal qualification scenarios so correct OWNER_GATE does not require an
operator to resume the five-task chain. Never clear a test gate automatically
unless the existing authority permits an evidenced resolution. Fault coverage
records must distinguish deterministic fault tests from actual live injections.

Run duration starts only when the real isolated pipeline is running, with
wall UTC + boot-aware monotonic evidence. One continuous run >=21600 seconds;
no accumulated previous runs, clock fabrication or idle sleep-only substitute.
On system clock/boot discontinuity fail acceptance explicitly. A detached
DevO-owned durable supervisor monitors the real pipeline, bounded deadlines,
fault schedule and status; it does not mutate lifecycle ledgers or issue
manual continue. Persist source-event timelines and checkpoint after events.
Its survival must be proven outside this Codex session, including daemon
restarts. Worker for P20.4 must remain non-terminal while qualification runs;
do not write COMPLETE merely after launching it. Do not leave a session-owned
foreground thread as the only owner of the six-hour run.

## P20.5 hard gate and final settlement

Require measured continuous >=6h and >=5 consecutively accepted real tasks;
zero manual continue/lifecycle repair, duplicate Worker/job/consumed handoff/
successor, wrong-task execution, fabricated successor, invariant escape,
silent stall, infinite retry, restart task regression, lost authority. All
supported faults must converge to automatic recovery or a correct durable
OWNER_GATE, all failures have incidents, all repeats share families, all
recoveries have strategy/outcome evidence, all gates state exact owner action.
Missing evidence fails acceptance; averages cannot hide a hard-zero failure.
Compute recovery success rate, mean/p95 latency, incidents/task, repeat rate,
review acceptance rate from actual source records with explicit denominators.

Final independent verdict only ACCEPT or CHANGES_REQUIRED. After remediation
and ACCEPT, settle through existing authority to P20.5 COMPLETE, null owner,
execution and gate; verify all invariants and restart terminality, no rerun or
duplicate history, tracked clean main, local commits only. No successor has
been invented. Roadmap re-baseline requires owner decision.
