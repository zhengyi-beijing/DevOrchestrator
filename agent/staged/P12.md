# P12 Unified AI Control Surface

Status: **PENDING DESIGN**

Design authorization: **DESIGN P12 / 2026-09-15**

Implementation authorization: **OWNER START REQUIRED**

Goal: make DevOrchestrator port 8770 the primary day-to-day control plane for projects and AI execution resources while retaining AIBroker port 8875 as its specialist configuration and diagnostic surface.

Scope:
- Add a versioned `/api/v1/control/*` read model that aggregates project/task/lifecycle state, active Planner/Implementer/Reviewer/Remediator work, watchdog/diagnostics, OWNER_GATE state, P11 evidence, conversation binding and AIBroker resource/execution facts.
- Preserve explicit available/stale/unavailable provenance and unknown fields; never infer health, quota, usage or cost.
- Extend the existing daemon-owned `ControlCommandCoordinator` into the only mutation consumer. HTTP handlers only authenticate, validate and durably enqueue closed command envelopes.
- Add loopback-only authenticated, CSRF-protected, idempotent and audited command submission with exact repository/task/lifecycle/gate state revision guards; pair ChatGPT heartbeat clients through short-lived single-use codes into revocable heartbeat-only capabilities stored hash-only by the daemon.
- Provide capability-advertised lifecycle actions (`continue`, `pause`, `resume`, `stop`, `retry`, `reconcile`, `approve_owner_gate`) and binding actions (`bind_conversation`, `unbind_conversation`, `rebind_conversation`) only where a safe existing coordinator/store adapter exists.
- Selectively forward-port the runtime conversation session/binding and owner-action safety contracts from `feature/conversation-control-plane` under port 8770; do not restore a second lifecycle authority on port 8766.
- Preserve current `/api/*` GET compatibility and keep standalone `start-web` read-only.
- Update dashboard, CLI and local ChatGPT/RDC integrations to consume the same API contract.
- Deliver in four bounded gates: unified reads; authenticated command transport/audit; guarded actions/conversation integration; operator UI/representative acceptance.

Acceptance:
- One 8770 overview call is enough to explain project state, current/next AI work, broker state, blocking conditions and P11 evidence with durable correlation IDs.
- Broker timeout/unavailability degrades only its section and retains unknown/stale provenance.
- Same command id plus the same canonical body is an exact replay; a different body conflicts; thread/process and crash-boundary tests prove no overwrite or duplicate effect.
- Non-loopback, unauthenticated, cross-origin, CSRF, oversized, malformed, unsupported and stale-state mutations fail closed.
- Every advertised action has deterministic success, stale identity, unsupported, replay, restart and cross-project isolation coverage; unavailable actions are never presented as executable.
- Conversation heartbeat uses a narrowly scoped paired-adapter capability; binding preserves one-to-one uniqueness, explicit unbound tombstones, liveness and claimed-request rebind guards without a second authority service.
- Existing GET routes and orchestration behavior remain compatible; standalone web stays read-only.
- A representative software-only DevOrchestrator scenario can be understood and normally controlled from 8770 without switching to 8875.
- Focused tests, full `python -m pytest tests_py -q`, Python compilation, JavaScript syntax, `git diff --check` and Graphify update pass.

Out of scope:
- Public internet exposure, built-in TLS, multi-user RBAC or a general remote-access product.
- AIBroker provider/account configuration and replacement of 8875 specialist diagnostics.
- Arbitrary prompt/shell/file/patch endpoints, scheduler/provider-policy redesign or inferred quota/cost.
- PID killing, weakened owner/hardware gates, or resuming `xray-hw-platform`.
- Wholesale merging of old feature-branch history.
