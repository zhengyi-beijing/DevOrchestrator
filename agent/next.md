## Objective and frozen direction

Extend the existing incidents pipeline as specified in `agent/staged/P20.md`
and `docs/P20_OWNER_REQUIREMENTS.md` section 4. Implement this phase only.
Capture Planner, Worker, Reviewer, Watchdog, TransitionExecutor, restart,
AIBroker/routing, ExecutionTransport and DurableJob failures. Repeated events
share one durable family and replay never increments twice.

expected invariant, actual outcome, regression class, replayability and
proposed/reproducible/verified/rejected/promoted status. Prefer bounded typed

not proof of production regression. Never auto-edit production test sources.

## Approved executable design

Extend the existing P16.10/P20.1 incidents pipeline into automatic failure harvesting plus typed regression promotion. Add nine durable-source detectors (Planner, Worker, Reviewer, Watchdog, TransitionExecutor, daemon/restart, AIBroker/resource routing, ExecutionTransport, DurableJob) that emit taxonomy-valid, sanitized incidents through the existing capture_incident/IncidentStore transaction, keying every occurrence on a durable source-event identity so repeated events share one project-scoped family and replay or restart never increments twice. Add a versioned RegressionCandidate contract plus an allowlisted, bounded JSON replay corpus that invokes real production logic (reusing convergence ReplayHarness) to produce durable proposed/reproducible/verified/rejected/promoted status with persisted rejection reasons. Bind a CPF-01 through CPF-10 observation matrix so harvesting and replay are proven observation-only and authority-preserving. Promotion means durable runtime evidence only: no production test-source writes, no synthetic forced-failure oracle as proof. Tests first with saved RED; local commit only.

### Risks / failure modes
- Signature drift: altering any existing detector's semantic payload would change failure_signature and break legacy family identity (including fam-689a96fe6ea9), the P20.1 identity test, and CPF-10 byte stability. Mitigation: taxonomy class is additive and non-signature; a test pins the legacy signatures byte-for-byte.
- Occurrence-key regression: deriving an occurrence_key from a tick, timestamp, or re-read position would double count on restart or replay and would break CPF-03, CPF-06, and CPF-09 observations. Mitigation: every key is a durable source-event identity with explicit replay/restart dedup tests per source.
- Detector blast radius in the daemon tick: nine new ledger readers increase the chance of an exception or slow read inside harvest_tick. Mitigation: keep per-detector try/except isolation, bound how many rows each detector scans, tolerate absent/malformed files, and keep all reads read-only.
- Vacuous verification: an oracle passing in both anchors (or a fixture-mode forced failure) would falsely claim a verified production regression. Mitigation: non-vacuity is a hard gate — identical defect and corrected outcomes force rejected with a persisted reason, and legacy synthetic candidates are permanently ineligible.
- Unsafe promotion: promotion must never auto-edit production test sources or touch tracked paths, including under a dirty worktree (CPF-05). Mitigation: runtime-only promotion with a path fence plus a working-tree snapshot test; legacy operator-driven promotion paths stay out of the automatic path and unchanged.
- Authority leakage: a detector or verification path that repaired a gate, consumed a handoff, or wrote a lifecycle ledger would violate CPF-01, CPF-02, CPF-04, and CPF-08 expectations. Mitigation: observation-only posture with byte-level zero-write assertions over lifecycle ledgers and explicit gate-never-cleared tests.
- Storage growth: new candidates, verification records, and corpus-linked evidence can grow unbounded. Mitigation: policy-clamped bounds with typed IncidentCapacityExceededError backpressure, and compaction that preserves totals, identity, verified/rejected status, and dedup keys without permitting re-actuation.
- Live-runtime contamination: tests or detectors that read or write the real runtime/ tree could disturb the running daemon or the preserved bootstrap evidence. Mitigation: all tests use tempfile runtime roots; detectors are strictly read-only; no runtime ledger editing in this task.
- Ledger-shape assumptions: fixtures here are derived from the current runtime files, and a differing production field shape could silently yield zero findings. Mitigation: treat missing/ambiguous evidence as unknown_requires_owner with an explicit reason rather than as success, and assert the unknown path in tests.
- Windows PowerShell 5.1 chaining: '&&'/'||' are not implemented and will fail verification commands, risking a false failure signal. Mitigation: PowerShell-safe sequencing with explicit exit-code checks (verified failure memory seed:p11b:rdc-powershell-5.1).
- Review-gate risk: scope creep into recovery actuation would exceed this phase and jeopardize the independent Technical Review ACCEPT required before P20.3. Mitigation: hold strictly to observation, classification, candidate contract, replay verification, durable status, and the CPF observation matrix.
